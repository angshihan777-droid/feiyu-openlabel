## Docker 演示步骤

1. 复制 `docker-production/env-templates/.env.ce.template` 为 `.env.ce`。
2. 设置强随机 `FY_JWT_SECRET`。
3. 确认 `FY_MEDIA_HOST_DIR` 指向可写入的宿主机目录。
4. 启动 PostgreSQL、FerretDB、Redis、web-api、web-app。
5. 在登录页点击“租户管理员 / 标注员 / 审核员”快速体验按钮，或输入验证码使用正式登录。
6. 在“批次管理”创建项目、上传视频、选择标注员池和审核员池。
7. 标注员登录，在“我的标注任务”打开任务，创建时间段、保存并提交。
8. 审核员登录，在“我的审核任务”查看匿名标注并审核。
9. 驳回两次观察退回原标注员；第 3 次驳回观察升级管理员。
10. 管理员在“裁决与统计”处理 escalated，并导出 CSV。

## 演示验收点

- 标注员响应看不到审核员 ID。
- 审核员响应看不到标注员 ID。
- 管理员能看到双方真实身份。
- 同名用户不能同时进入同一批次的标注/审核池。
- 两个视频生成两个 Unit。
- 触点区间被前端和后端同时拒绝。
- 第 3 次驳回进入 escalated。
- 强制通过的最新快照出现在按日统计。

## 请人工决策

### 决策 1：统计自然日

- A（推荐）：继续 UTC，行为稳定、测试已覆盖。
- B：增加租户时区，按租户本地自然日统计。

影响：B 更符合正式 SaaS，但需要租户时区配置、迁移和跨时区测试。

### 决策 2：时长探测

- A（推荐）：保留 OpenCV，失败时要求人工确认时长。
- B：部署 `ffprobe`，提高格式覆盖和稳定性。

影响：B 增加系统依赖，但更适合 MOV/MKV 等复杂视频。

### 决策 3：管理员 UX

- A（推荐本轮接受）：批次 ID 和标注员 ID 手工输入。
- B：增加项目/批次下拉框和批次内标注员下拉框。

影响：B 只是前端可用性增强，不改变数据契约。

### 决策 4：生产存储

- A（推荐比赛/单机）：当前本地租户目录。
- B：MinIO/S3 预签名上传。

影响：B 更适合多实例和 CDN，但需要额外的租户隔离、预签名和清理策略。

### 决策 5：真实环境验收

- A（推荐）：在具备 Docker 的机器上先跑 PostgreSQL/FerretDB/Redis 整链路。
- B：直接部署后再验收。

影响：A 能在上线前发现 ORM、迁移、中间件和真实视频问题。

### 决策 6：性能目标

方案文档提到提交 `<500ms`、统计 `<1s`、并发 100 用户。目前没有性能环境，是否本轮必须执行需要确认。

### 决策 7：前端包体优化

- A（推荐）：本轮先保证功能，接受构建的 chunk size warning。
- B：继续拆分 Element Plus 和视频编辑器依赖，目标降低首屏体积。

影响：B 属于性能优化，不改变业务功能，但需要额外回归路由与懒加载。
